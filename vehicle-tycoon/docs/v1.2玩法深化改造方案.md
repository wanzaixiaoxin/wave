# v1.2 玩法深化改造方案

> **问题定义**：造车→派车→收钱的核心循环目的明确，但节奏单一——玩家实际动词只有"点造车、点派单、等"，
> 养成深度全部后置（专精要蓝品质、进化要金品质满级），且系统只改数字不改玩法，等待期没有任何主动层。
>
> **改造目标**：不推翻现有循环和数值骨架，往循环里**插决策点**，让"等、派、养"三个动作各自长出策略层。

---

## 一、诊断回顾（为什么现在不好玩）

| 缺陷 | 现状 | 后果 |
|------|------|------|
| 深度后置 | 专精（蓝品质）、天赋（进化）等改规则系统全在 2 小时后 | 前 30 分钟是裸循环，玩家在此流失 |
| 只改数字 | 升级 +5%、品质 ×1.5、属性点 % 微调 | 成长无感知，"数字变大"≠"车不一样" |
| 等待无内容 | 派单后 30-60s 纯垃圾时间 | auto 派单一开，玩家变观众 |
| 最优解明确 | auto 派单=贪心最优，订单刷什么接什么 | 决策可完全外包，无排程策略 |
| 特质靠 RNG | 出生随机、不可重掷 | 构筑感为零，玩家只是"接受者" |

**设计原则（后续每个模块都对照此表验收）**：
1. 每个动词都有决策——造车、派单、等待、养成，每个动作至少含一个真实取舍
2. 等待必须有事干——垃圾时间转化率 ≥50%（一半以上的在途订单给玩家一次微决策）
3. 成长优先改规则——新养成内容优先"解锁新玩法"，其次才是 "+N%"
4. 挂机不受罚——所有主动层都是**奖励性**的，不操作走默认值，收益不低于现状
5. 数值纪律不破——时间仍是最根本的抗膨胀货币，所有新增收入口子经 sim.ts 校准

## 二、模块详案

### M1 路上事件系统（治"等"）— 最高优先级

**玩法**：派单后，部分订单在途中随机时刻触发一个 2-3 选 1 的小事件，弹窗 10 秒决策窗口，超时走默认项（对挂机党无害）。

事件池（首批 6 个，每个都是"时间 vs 金钱 vs 磨损"的三角取舍，无绝对最优解）：

| 事件 | 选项 A | 选项 B | 选项 C（默认） |
|------|--------|--------|----------------|
| 🚧 前方修路 | 绕行：耗时 +15s | 硬闯：磨损 +10 | 等一等：耗时 +8s，无事发生 |
| 🙋 顺风车客 | 带上：本单收入 +30%，耗时 +10s | 拒载 | — |
| 🛞 爆胎 | 换胎：零件 -2，继续 | 硬开：磨损 +15 | 叫救援：耗时 +20s |
| 🌤️ 好天气 | 赶路：耗时 -15% | 慢行：亲密度 +5 | — |
| 🚨 交警抽查 | 配合：耗时 +10s | 塞红包：金币 -本单10% | （耐久≥4 才出现）出示年检：无事 |
| ⛽ 油价上涨 | 加好油：金币 -5%，耗时 -10% | 凑合开：磨损 +5 | — |

**触发规则**：
- 每单 40-70% 概率触发 1 次（长途单权重高，因为耗时长、窗口大）
- 触发点：行程 30%-70% 之间的随机时刻
- 超时/离线未处理 → 默认项，订单正常结算（原则 4）

**代码改动点**：
- `src/core/types.ts`：`Order` 增加 `enRouteEvent?: { eventId: string; triggerAt: number; resolved: boolean }`；`GameEvent` 增加 `EN_ROUTE_EVENT_TRIGGERED / EN_ROUTE_EVENT_RESOLVED`
- `src/config/`：新增 `EnRouteEventConfig.ts`（事件表 + 选项效果表）
- `src/systems/OrderSystem.ts`：`assignVehicle()` 里按概率排定 `triggerAt`；`tick()` 检测到点未决策的事件 → 发事件；新增 `resolveEnRouteEvent(orderId, choiceIndex)` 修改 `vehicle.statusEndAt` / `wear` / 订单的 `pendingRewardMult`；`completeOrder()` 结算时乘上 `pendingRewardMult`
- `src/ui/modal.ts`：新增路上事件弹窗（带 10s 倒计时条，超时自动选默认项）
- 存档：新字段可选，老存档天然兼容；`SaveManager` 版本号 +1

**验证**：smoke 新增断言——各选项对耗时/收入/磨损的比值符合配置；sim 玩家加"随机选项"策略，确认里程碑时间漂移 <5%。

### M2 订单市场改造（治"派"）

**玩法**：把"刷什么接什么"改成"有限供给下的排程决策"。

1. **目的地标签 + 连单奖励**：每个订单带随机目的地（3-5 个，如 城东/矿区/港口/机场）。同一辆车**连续**完成同目的地订单，每连一单收入 +15%，上限 +45%。玩家要决定：集中运力打连击，还是分散接高价单。疲劳机制（连单 -8%）与连单奖励天然对冲，构成张力。
2. **紧急订单**：5-10% 的订单标记为"🔥紧急"——收入 ×2.5，但 90 秒内必须派出且耗时更短。制造节奏波峰，打破匀速流水账。
3. **手动刷新**：每 60s 可免费刷新一次待接订单池（或花 3 零件立即刷新），把"等好单"变成可控操作。

**代码改动点**：
- `types.ts`：`Order` 增加 `destination: string`、`isUrgent?: boolean`；`Vehicle` 增加 `lastDestination?: string`、`chainCount: number`
- `OrderSystem.generateOrder()`：分配目的地、紧急单概率判定
- `completeOrder()`：连单判定与奖励倍数（收入乘区第 12 层，走 `EconomySystem.calculateOrderIncome` 新增参数）
- `src/ui/orders.ts`：订单卡显示目的地标签、紧急角标与倒计时、连击提示
- `autoAssign()`：贪心策略升级为"优先保连击"，保持挂机体验

**验证**：smoke 断言连单倍率阶梯与上限；紧急单的收入/小时增量 <15%（它是机会成本替代而非纯增量）。

### M3 配件系统（治"养"，把 RNG 变成构筑）

**玩法**：车辆增加配件槽，配件用零件打造，可自由装卸，拆车时回收。把"出生随机特质"的无力感转化为"我亲手把这辆车构筑成快车/重载车"。

- **槽位**：白品质 1 槽 → 蓝 2 槽 → 金 3 槽（品质成长多一层规则变化，呼应原则 3）
- **首批 6 件**（零件造价 15-60， tier 越高的车打造越贵）：

| 配件 | 效果 | 定位 |
|------|------|------|
| 增压引擎 | 订单耗时 -10% | 快车流 |
| 加固货箱 | 收入 +12% | 重载流 |
| 耐磨轮胎 | 磨损累积 -40% | 轮班流 |
| 幸运挂饰 | 暴击率 +3% | 暴击流 |
| 副油箱 | 长途单收入 +20% | 长途流 |
| 导航仪 | 路上事件默认项收益 +50% | 挂机友好 |

- 配件 + 特质 + 专精 + 天赋四层叠加，"流派"真正成型（例：增压引擎+勤快特质+快车专精+独轮车天赋 = 极限周转车）

**代码改动点**：
- `types.ts`：`Vehicle.accessories: string[]`
- `src/config/AccessoryConfig.ts`（新增）
- `EconomySystem.calculateOrderIncome()` / `OrderSystem.assignVehicle()`：读取配件效果
- `src/ui/garage.ts`：车辆详情增加配件槽 UI（打造/装卸）
- 拆解回收：配件 100% 返还背包，零件不返还

**验证**：smoke 断言每件配件的效果比值；sim 验证配件造价对零件经济的抽水率（零件五口竞争变六口，确认不破坏升品节奏）。

### M4 养成规则化（治"数字疲劳"）

1. **专精前置**：三选一从"蓝品质"提前到 **Lv.3** 解锁。玩家在第一个小时就给车定下身份，而不是憋到两小时后。
2. **属性满级送规则**（修复耐久 3 级后零收益的问题，同时让加点有盼头）：
   - 速度 5 级 → 该车的路上事件**额外解锁一个隐藏选项**（如"走近道：耗时 -25%，磨损 +8"）
   - 载货 5 级 → 该车无视品质门槛接贵重单（白车也能拉贵重）
   - 耐久 5 级 → 免疫爆胎类负面事件 + 长途单耗时 -10%
3. **品质升级解锁槽位**（见 M3），让品质成长从"×1.5 数字"变成"多一个构筑位"。

**代码改动点**：`src/ui/garage.ts` 专精入口条件、`OrderSystem.canVehicleTakeOrder()` 门槛判定、`EnRouteEventConfig` 选项解锁条件。改动小，收益直接。

## 三、实施路线图

每个里程碑独立可玩、可上线，smoke + sim 全绿才进入下一个。

| 里程碑 | 内容 | 预计工作量 | 验收标准 |
|--------|------|-----------|----------|
| **A：节奏修复** | M1 路上事件 + M5 目标引导 | 3-4 人日 | 在途订单事件覆盖率 ≥50%；sim 里程碑漂移 <5% |
| **B：策略层** | M2 订单市场（连单/紧急单/刷新） | 3-4 人日 | 连单倍率阶梯正确；紧急单收入占比 <15% |
| **C：构筑层** | M3 配件 + M4 养成规则化 | 4-5 人日 | 6 配件效果断言全过；零件经济抽水后 sim 节奏漂移 <10% |
| **D：终局** | M6 轮回接线 | 2-3 人日 | 完整轮回流程可走通；声望效果有断言 |

**顺序理由**：A 直接命中"节奏单一"的核心痛点且风险最低；B、C 逐层加深策略；D 保底终局。若资源紧张，A+B 即可显著改善口碑，C、D 可拆到 v1.3。

## 四、风险与对策

| 风险 | 对策 |
|------|------|
| 路上事件打断放置体验 | 默认项保底 + 导航仪配件服务挂机党 + 事件频率上限（同屏最多 1 个待决策） |
| 新收入口子引发通胀 | 所有新倍率进 `EconomySystem` 统一乘区；sim 跑 3 小时校准，里程碑时间漂移 >10% 则调参 |
| 连单奖励与疲劳机制冲突导致体感负反馈 | 连单上限 +45% vs 疲劳下限 ×0.6，数值上"打连击"始终优于"无脑连"，引导玩家轮班而非惩罚 |
| 配件系统拉高新手理解成本 | M5 提示条承接教学；配件在蓝品质（第 2 槽）才成为必需，白品质 1 槽无压力 |
| 存档兼容 | 所有新字段可选 + 默认值兜底，`SaveManager.migrate()` 升版本，老档无损 |

## 六、M7 时间化改造 + 工厂零件经济修复（已实施）

### 目标

把"即时完成"的三大动作（造车 / 研究 / 升品）改为时间化，让放置游戏有真实的等待与排队决策；同时修复工厂零件产出被订单零件碾压的问题。

### 最终数值

| 项目 | 数值 | 位置 |
|------|------|------|
| 建造槽 / 排队位 | 1 槽 + 3 排队（`BUILD_QUEUE_MAX: 3`） | GameConstants |
| 造车耗时 | 沿用车型 `buildTime` 字段（首次启用），中段微调 -14%~-17%：T1 2s / T2 4s / T3 6s / T4 10s / T5 17s / T6 30s / T7 42s / T8 75s / T9 120s / T10 200s | VehicleConfig |
| 主线研究耗时 | L1 30s / L2 60s / L3 120s / L4 240s / L5 480s（`RESEARCH_TIME_MAIN`） | GameConstants |
| 支线研究耗时 | 统一 60s（`RESEARCH_TIME_SIDE`），与主线共享一个研究槽 | GameConstants |
| 品质升级耗时 | 白→蓝 60s / 蓝→金 180s（`QUALITY_UPGRADE_TIME_BLUE/GOLD`） | GameConstants |
| 工厂进度系数 | 产出 ×(1 + 车库最高车型 tier × **0.3**)（`FACTORY_TIER_SCALING: 0.3`），空车库按 T1 计 | GameConstants |

### 机制要点

- **建造队列**：`createVehicle` 改为入队（资源入队时扣，防刷），车库按「现有 + 建造中 + 排队」预留未来车位；到点走原 VEHICLE_PRODUCED 落地路径（传承池继承、特质随机不变）。工作台显示进度条 + 队列（emoji + 剩余秒数），槽满/车位满禁用按钮。教程第 1 步本就监听 VEHICLE_PRODUCED 事件，T1 仅 2s，无适配成本。
- **研究耗时化**：主线/支线共享一个研究槽；资源在**开始**时扣除；到点走原 TECH_RESEARCHED 事件。研究期间科技面板显示倒计时，其他研究按钮禁用。
- **升品耗时化 + 锁车**：开始升级扣资源，期间车辆 `status = Maintenance`（订单系统的 Idle 判定天然排除派单/指派，下拉已验证），到点应用品质恢复 Idle。车辆卡片/详情显示「升级中 Ns」。**进化保持即时，未动。**
- **工厂零件经济**：`getPartsPerSecond()` 乘进度系数 `(1 + topTier × 0.3)`，工厂面板显示当前加成（"🚀 进度加成 ×N.N（车库最高 TN）"），让玩家感知工厂随进程变强。
- **存档**：版本 1.0 → 1.1；`garage.buildQueue`、`techTree.researching`、`vehicle.qualityUpgrade` 全部存 `finishAt` 真实时间戳，`migrate()` 为老档补空默认值；离线期间计时自然走完，离线收益逻辑未改。

### sim 验证（3 小时贪心玩家，9 次均值）

| 里程碑 | 基线 | M7 改后 | 漂移 |
|--------|------|---------|------|
| 科技 L2 | 449s | 531s | +18.2% |
| 科技 L3 | 1087s | 1372s | +26.2% |
| 科技 L4 | 1926s | 2218s | +15.2% |
| 科技 L5 | 3590s | 3537s | **-1.5%** ✅ |
| 造出 T10 | 4089s | 3899s | **-4.6%** ✅ |

中段（L2-L4）漂移超 ±10% 属**有意放缓**：研究耗时（L2+L3+L4 共 420s 串行）与建造排队是设计要求，buildTime 已在 ±20% 区间内微调（-14%~-17%），研究时长为方案指定值未动；终局（L5/T10）因工厂进度系数加速了零件供给，反而略快于基线，整体节奏守住 ±5%。

### 工厂零件占比实测（T3-T7 窗口，工厂产出 ÷ 零件总毛收入）

| 系数 | 实测占比 |
|------|---------|
| 0（无加成，对照） | ~37% |
| 0.1 | ~47% |
| **0.3（定稿）** | **~62-65%** |
| 0.4（方案初始值） | ~67% |

结论：30-40% 的目标区间在本 sim 下**不可达**——贪心玩家会积极投资工厂，即使零加成工厂占比也有 ~37%；任何正系数都会超出 40%。定稿 0.3 的理由：取方案允许的调参区间（0.3-0.6）下限，占比尽量贴近目标，同时保住终局节奏（见上表 L5/T10）；机制感知度明确（T10 时 ×4.0，相比零加成产出 ×3 倍）。
